# 19 — Приймання вебхука від Grafana

**Фаза:** 5 — Користувачі та персональні алерти
**Залежності:** 16
**Блокує:** 20

## Контекст

Contact point Grafana має **один** `chatid`. Задача 12 назвала це усвідомленим
компромісом і бачила єдиний вихід — повернути `alerts.js` у бота, дублюючи
логіку порогів. Webhook — третій шлях: пороги, `for`, `noDataState` і шаблони
лишаються в Grafana, бот відповідає лише за адресацію.

Перевірено по `/api/alert-notifiers`: contact point типу `webhook` має поля
`authorization_scheme` + `authorization_credentials` (обидва secure), тобто
`Authorization: Bearer <token>` доступний. Фолбек — Basic auth (`username` +
`password`), він є завжди.

## Чому автентифікація тут критична

Ендпойнт — **множник**: один HTTP-запит перетворюється на N повідомлень у
приватні чати людей, від імені бота, якому вони довіряють. Без перевірки
будь-хто, хто вгадає шлях (а публічний репозиторій його прямо називає),
розсилає підписникам що завгодно: «терміново вимкніть автоматику», фішинг на
облікові дані Grafana. Плюс безкоштовне вичерпання ліміту Telegram.

Це якісно гірше за діру з задачі 13 §5, де незнайомець лише **читав**
телеметрію. Тут — **запис у чужі приватні чати**.

## Кроки

1. Секрет `GRAFANA_WEBHOOK_TOKEN` — 32 випадкові байти base64url.
2. `webhookAuthorized(header, expectedToken)` — чиста функція. Порівнювати
   **дайджести**, а не сирі рядки: `timingSafeEqual` кидає на різній довжині,
   і сам виняток злив би довжину токена.
3. **Незаданий секрет мусить давати `false`**, а не «немає очікуваного →
   пропускаємо». Окремий тест.
4. Відповідь на невдачу — `401` з порожнім тілом, **без** `WWW-Authenticate`
   (не запрошуємо браузер до діалогу) і без деталей.
5. `parseGrafanaWebhook(payload)` — чиста функція. **Беремо
   `alerts[].annotations`, а не верхньорівневий `message`**: `message`
   рендериться шаблоном `deye-telegram` (див. `docs/grafana-alerting.md`),
   тобто вже зібраний для людини й зламається, щойно шаблон змінять.
   Анотації — стабільний контракт: `summary` / `description` / `resolved`.
6. Обрізати довжини: Telegram відхиляє повідомлення понад 4096 символів, і
   одне довге `description` втратило б **увесь** алерт.
7. Фолбек для `fingerprint`: у ручному тесті з UI Grafana його може не бути, і
   без фолбеку всі тестові алерти схлопнуться в один dedup-ключ.
8. Дешеві додаткові перевірки: `Content-Type: application/json` → інакше 415;
   відкидати алерти зі `startsAt` старішим за 24 год (захист від реплею).
9. Розширити `redact()` у `helpers.js` на `GRAFANA_WEBHOOK_TOKEN` — зараз він
   вирізає лише `/bot<token>`.

## Критерії готовності

- [x] Запит без `Authorization` → 401
- [x] Запит з чужим токеном → 401
- [x] Порожній `GRAFANA_WEBHOOK_TOKEN` → усі запити 401, ендпойнт не відкритий
- [x] `fly logs` не містить токена вебхука
- [x] Парсер: firing, resolved, кілька алертів у батчі, `alerts` не масив
- [x] Алерт **без** `labels.inverter` парситься в `inverterId === null`
- [x] Відсутній `fingerprint` → різні dedup-ключі для різних елементів
- [x] Наддовгий `description` обрізається, повідомлення не втрачається


## Результат (4 вер 2026)

```
без Authorization        → 401
з чужим токеном          → 401
з правильним             → 200 ok
```
Секрет `GRAFANA_WEBHOOK_TOKEN` у Fly secrets, у логах не з'являється.
