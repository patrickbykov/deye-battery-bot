## Контекст

### README розходиться з реальністю

- Описує деплой на **Render.com** (Background Worker, Build Command, Start Command). Проєкт живе на **Fly.io** — є `fly.toml`, `Dockerfile`, працюючий застосунок `deye-battery-bot`. Розділ стух приблизно на 8 комітів.
- Документує `POLL_INTERVAL` як налаштування — **його ніде не читають**. `index.js:91` має захардкоджені `setTimeout(r, 1000)`.
- Не згадує `ADMIN_CHAT_ID`, SQLite, волюм, multi-inverter і колектор.
- Інструкція локального запуску **не працює**: `cp .env.example .env && npm start`, але в проєкті немає ані `dotenv`, ані прапорця `--env-file` (на Node 18 його й не існувало). Файл `.env` просто не завантажиться.
- Заявляє MIT, але **файлу LICENSE у репо немає**.

### `.env.example` розходиться з кодом

Містить `INFLUXDB_URL`, `INFLUXDB_ORG`, `INFLUXDB_TOKEN` — **бот не читає жодну з них** (бот ходить у Influx винятково через Grafana proxy). Це змушує заводити зайвий креденшел, який нікому не потрібен, — непотрібна поверхня атаки. Після задачі 03 ці змінні стануть потрібні **колектору**, і саме там їм місце.

Відсутні `PORT` (`config.js:8`) і `ADMIN_CHAT_ID` (`config.js:9`).

### Бекапу БД немає

**Оновлено 4 вер 2026: після фази 5 бекап переходить з «бажано» в
«обов'язково».** У БД тепер не лише підписки, а й **рішення про доступ до
чужих будинків**: втрата волюма означає, що всі стають `pending` і адмін
схвалює всіх заново, не пам'ятаючи, кому що дозволяв. `/export` має
вивантажувати `users` разом із `subscriptions`. Деталі — задача 24.

`data/bot.db` на Fly-волюмі. **Підписки — єдиний невідновлюваний стан у системі**: інвертори перевідкриються з InfluxDB через discovery, алерти живуть у Grafana, метрики в Influx. Підписки не відновить ніщо. Fly-волюм прив'язаний до одного хоста; втрата машини = втрата всіх підписок без шляху відновлення.
