# 10 — Переписати `commands.js`

**Фаза:** 3 — Multi-inverter
**Залежності:** 08 (без template-змінної `/graph` віддає однакові картинки), 09 (без discovery нема на що підписуватись)
**Блокує:** 11

## Контекст

Зараз `commands.js` експортує пласку мапу з чотирьох команд (`/start`, `/help`, `/status`, `/graph`), усі без аргументів, інвертор захардкоджений у Flux-запиті. Потрібні команди з аргументами й робота через підписки.

## Команди

### Користувацькі

| Команда | Опис |
|---|---|
| `/list` | Усі відомі інвертори з БД |
| `/subscribe <id>` | Підписатись (з валідацією через `getInverter`) |
| `/unsubscribe <id>` | Відписатись |
| `/mysubs` | Свої підписки |
| `/status` | Стан по кожній підписці — одне повідомлення на інвертор |
| `/graph` | Графік по кожній підписці |
| `/help` | Оновлена довідка |

Перехід з мапи `commands` на `{ simpleCommands, argCommands, parseCommand }`, парсинг `/^(\/\w+)(?:\s+(.+))?$/`.

## Баг, закладений у вихідному плані — не повторити

`docs/plans/2026-03-06-multi-inverter-plan.md:734` робить:
```js
parseCommand(text.toLowerCase())
```
Лоуеркейситься **весь рядок разом з аргументом**. Далі `handleSubscribe` викликає `getInverter('deye-sun-15k')`, а в таблиці лежить `"Deye-SUN-15K"` — `TEXT PRIMARY KEY` у SQLite має BINARY-колацію, тобто порівняння регістрозалежне.

**Результат: кожен `/subscribe` відповідатиме «інвертор не знайдено».** І це виглядатиме як проблема discovery, а не парсингу.

Правильно: лоуеркейсити **тільки саму команду**, аргумент лишати як є.
```js
const m = text.trim().match(/^(\/\w+)(?:\s+(.+))?$/);
const cmd = m?.[1].toLowerCase();
const arg = m?.[2];          // без toLowerCase
```
Альтернативно — оголосити `id TEXT PRIMARY KEY COLLATE NOCASE` у `db.js`. Один із двох варіантів, не обидва наосліп.

## Оновлено 4 вер 2026 — сигнатура хендлерів

Фаза 5 додає inline-клавіатури, і це змінює вимогу **до цієї задачі**, а не
після неї. Хендлери мусять приймати контекст, а не голий `chatId`:

```js
{ chatId, messageId, callbackId, from, chatType }
```

Зараз `index.js` передає лише `msg.chat.id`. Без `messageId` неможливо
редагувати клавіатуру на місці (`editMessageReplyMarkup`), без `from` —
перевірити адміна, без `chatType` — відсікти групи. Якщо не закласти це
одразу, задача 17 переписуватиме щойно написаний код.

**Питання регістру аргументу знімається саме собою.** У новому UX користувач
більше не вводить id руками — він тицяє кнопку, а в `callback_data` їде
`inverters.rowid`. Тобто `COLLATE NOCASE` не потрібен; лишаємо BINARY і не
лоуеркейсимо аргумент, як і сказано вище.

## Решта кроків

1. `handleStatus` / `handleGraph` — цикл по `getSubscriptions(chatId)`. Порожній список → підказка про `/list` і `/subscribe`, а не мовчання.
2. `handleGraph` викликає `renderGrafanaPanel(inverter)` з повним об'єктом рядка БД (`dashboard_uid`, `panel_id`, `id`) — саме таку сигнатуру вже має `grafana.js:30`.
3. Флуд-контроль: при кількох підписках `/status` шле кілька повідомлень поспіль. Telegram ліміт ~30 msg/s — додати паузу між відправками (обробка `429` — задача 13).
4. Прибрати з `/help` хардкод `Deye SUN-15K-SG05LP3-EU-SM2` і рядок про алерт із зашитим порогом 20% (`commands.js:81-83`).
5. Не віддавати користувачу сире тіло помилки Grafana — див. задачу 13.

## Критерії готовності

- [x] `/list` показує всі інвертори з БД
- [x] **`/subscribe Deye-SUN-15K` спрацьовує** (регістр аргументу збережено) — головна перевірка бага вище
- [x] `/subscribe неіснуючий` → зрозуміла відмова, не мовчанка
- [x] `/mysubs` відображає підписки, `/unsubscribe` їх знімає
- [x] `/status` без підписок → підказка, а не порожнеча
- [x] З двома інверторами: `/status` → два різні повідомлення, `/graph` → **два різні графіки**
- [x] Команда з аргументом там, де його не чекають (`/status foo`), не валить обробку


## Результат (4 вер 2026)

`commands.js` переписаний як фабрика `createCommands({store, telegram, grafana, log, sleep})`
з ін'єкцією залежностей — інакше 16 тестів довелося б писати з моками мережі.

Перевірено в проді:
```
/list      → 📋 Доступні об'єкти: 2512151417, test
/subscribe 2512151417 → ✅ Підписано на 2512151417
/status    → 🔋 2512151417, SOC 98%, 55.2 V, 0.9 A, 42.0 W, 26.0 °C
/status без підписок → підказка про /list і /subscribe
```

### Баг, знайдений живим тестом, а не тестами

`/subscribe` мовчав, у логах — `FOREIGN KEY constraint failed`. Підписка
посилається на `users(chat_id)`, а рядка користувача ніхто не створював:
`upsertUser` планувався аж на задачу 17. Юніт-тест цього не спіймав, бо
харнес створював користувача сам — саме так дірка й сховалась.

Виправлено: `/subscribe` і `/unsubscribe` створюють користувача й оновлюють
нік. Два регресійні тести.
