# 17 — Реєстрація й вибір інверторів у боті

**Фаза:** 5 — Користувачі та персональні алерти
**Залежності:** 15, 10, 11
**Блокує:** 18

## Контекст

Користувач має сам обрати об'єкти, які його цікавлять, і подати заявку.
Рішення власника: **команди бота з inline-кнопками**, без Mini App.

## Кроки

1. **Перевірка `msg.chat.type === 'private'`** — найдешевша перевірка тут і
   одна з найважливіших: інакше `chat_id` групи потрапить у `users` як
   «людина», а `from.id ≠ chat.id` зламає всю логіку підписок.
2. `/start` → `upsertUser(chat_id, username, first_name)` — нік оновлюється
   при **кожному** контакті, бо люди їх міняють. Далі гілка за статусом.
3. `subs-keyboard.js` — чисті функції: `buildKeyboard(inverters, checked)`,
   `parseCallback(data)`, `readChecked(replyMarkup)`.
4. Екран вибору — одне повідомлення, яке редагується на місці:
   ```
   Оберіть інвертори, на які хочете отримувати сповіщення:
     [☑️ Будинок на Лесі Українки]     callback_data: "t:3"
     [⬜ Склад]                         callback_data: "t:7"
     ─────────────────────────────
     [📨 Надіслати заявку]              callback_data: "req"
   ```
5. **`callback_data` містить `inverters.rowid`, а не `id`.** Ліміт Telegram —
   64 байти; `id` це SN інвертора, сьогодні короткий, завтра ні, і збій буде
   тихий: Telegram відхилить клавіатуру цілком. `inverters` — звичайна
   rowid-таблиця, нової колонки не треба. Заодно знімається вся проблема
   регістру з задачі 10.
6. **Стан галочок живе в самій клавіатурі, не в БД.** `callback_query` містить
   `message.reply_markup` — звідти й читаємо. Наслідок: поки заявку не
   надіслано, `subscriptions` і `status` **не змінюються**, тобто схвалений
   користувач не втрачає доступ через те, що просто відкрив екран. Стан
   переживає рестарт процесу, бо живе в Telegram. Фолбек, якщо читання
   `reply_markup` виявиться ненадійним — таблиця чернеток.
7. Тик → `editMessageReplyMarkup` + `answerCallbackQuery(id, {text: 'Додано'})`
   (тост, без спаму новими повідомленнями).
8. Для **схваленого** користувача екран додає попередження: зміна набору
   поверне заявку на розгляд і до схвалення сповіщення не надходитимуть.
   Втрата доступу не має бути несподіванкою.
9. «Надіслати заявку»: 0 обраних → тост «Оберіть хоча б один інвертор».
   Інакше — `replaceSubscriptions()` однією транзакцією разом зі
   `status = 'pending'`, `requested_at = now`.
10. Роутинг callback-ів — **окрема `Map` + `typeof handler === 'function'`**.
    Та сама дірка з `__proto__`, що в задачі 11, але для `callback_data`, яка
    довільна: клієнт може надіслати будь-що, не лише те, що ми намалювали.

## Критерії готовності

- [ ] `callback_data` для найдовшого реального SN ≤ 64 байти — покрито тестом
- [ ] Бот, доданий у групу, **не** створює запис у `users`
- [ ] Галочки в клавіатурі відповідають набору підписок
- [ ] Відкриття екрана схваленим користувачем не змінює його статус
- [ ] Заявка без жодного обраного інвертора не подається
- [ ] Нік оновлюється в БД після зміни його в Telegram
- [ ] `callback_data` виду `__proto__:x` не викликає нічого
