# 18 — Схвалення в Telegram, гейт доступу, `/forgetme`

**Фаза:** 5 — Користувачі та персональні алерти
**Залежності:** 17
**Блокує:** 24

## Контекст

Заявку треба схвалити. Веб-адмінка (задача 23) робиться пізніше й навмисно —
після цієї задачі система вже працює наскрізь: людина реєструється, адмін
схвалює з телефона просто в Telegram. Веб стає зручністю, а не блокером.

Ця задача заодно закриває **задачу 13 §5** («немає жодної авторизації»).
Метрований рендер `/render/d-solo` на Free-плані Grafana стає недосяжним для
незнайомця: щоб дійти до `renderGrafanaPanel()`, треба бути `approved`.

## Життєвий цикл

```
   новий ──(обрав об'єкти, «Надіслати заявку»)──▶ pending
                                                    │
                                    ┌───────────────┴──────────────┐
                              (адмін схвалив)               (адмін відхилив)
                                    ▼                              ▼
                                approved                       rejected
                                    │                              │
                    (змінив набір і надіслав заявку)      (подав заявку знову)
                                    │                              │
                                    └──────────▶ pending ◀─────────┘

   будь-який стан ──(/forgetme + підтвердження)──▶ запису немає
```

## Кроки

1. **Гейт доступу.** `/status` і `/graph` доступні тільки `approved`. Решті —
   пояснення за статусом, а не мовчанка:

   | Статус | Що бачить |
   |---|---|
   | новий | привітання + «Обрати інвертори» |
   | `pending` | «Заявка на розгляді» + «Змінити вибір» |
   | `approved` | меню: `/status`, `/graph`, «Мої підписки», «Змінити вибір» |
   | `rejected` | «Заявку відхилено, спробуйте пізніше» + «Подати заявку знову» |

2. **`pending` вимикає все**, включно з раніше схваленими об'єктами — рішення
   власника. Наслідок, який треба розуміти: людина, яка ввечері додала другий
   будинок, до схвалення не отримає попередження й по першому. Пом'якшення —
   адмін схвалює двома тапами, не заходячи у веб.

3. **Повідомлення адміну** в `ADMIN_CHAT_ID`:
   ```
   🆕 Нова заявка
   @username (Ім'я)
   Інвертори: Будинок на Лесі Українки, Склад
   [✅ Схвалити]  [🚫 Відхилити]     a:ok:<chatId> / a:no:<chatId>
   ```
   - Перевірка `from.id === ADMIN_CHAT_ID` **у самому хендлері**, не лише при
     показі кнопок: `callback_data` може надіслати будь-хто, хто вгадає формат.
   - Текст через `escapeHtml`. Інакше нік з `<` покладе повідомлення з
     `400 can't parse entities` — та сама пастка, що описана в
     `docs/grafana-alerting.md`. Тут це ще й вектор: людина сама обирає собі ім'я.
   - Дебаунс: не частіше одного повідомлення на людину за 10 хв. Без нього
     відхилений, який має право подавати заявку знову, засипле адміна.
   - Після рішення — `editMessageText` на «✅ Схвалено @username», кнопки
     прибираються, щоб не тицьнути двічі. Користувачу — окреме сповіщення,
     інакше він не дізнається, що доступ відкрито.

4. **Відмова не остаточна.** Кажемо прямо, що заявку відхилено, і що можна
   спробувати пізніше. `rejected` — це «не зараз», а не «ніколи». Окремий
   жорсткий `blocked` не вводимо, поки не з'явиться реальна потреба.

5. **`/forgetme`** — видаляє запис користувача, каскадом і підписки; після
   цього людина для системи знову незнайомець. Дія незворотна, тож
   **обов'язково крок підтвердження окремою кнопкою**. Доступна в будь-якому
   статусі, включно з `rejected` — саме тим, кому відмовили, найчастіше й
   потрібно прибрати про себе дані.

6. **`ADMIN_CHAT_ID` нарешті завести у Fly secrets.** Задача 07 свідомо його
   пропустила: «секрет без споживача лише додає плутанини». Тепер споживач є,
   і без секрету заявки нікуди не підуть.

## Критерії готовності

- [x] `a:ok:<чужий_chat_id>` від не-адміна не робить нічого
- [x] Нік з `<` у імені не ламає повідомлення адміну
- [x] `pending` не отримує ні `/status`, ні `/graph`, ні алертів
- [x] Після схвалення користувачу приходить сповіщення
- [x] Відхиленому видно, що його відхилено, і він може подати заявку знову
- [x] `/forgetme` без підтвердження нічого не видаляє
- [x] Після `/forgetme` і повторного `/start` людина проходить шлях з нуля
- [x] `ADMIN_CHAT_ID` є у `fly secrets list`


## Результат (4 вер 2026)

Наскрізний сценарій у проді:

```
📨 Заявку надіслано на розгляд.  Обрані об'єкти: • 2512151417
✅ Схвалено @PetroBykov
✅ Доступ відкрито. /status — поточний стан, /graph — графік.
```

Гейт перевірено тестом, який стежить не за текстом відповіді, а за тим, що
запиту до Grafana **не було**: перевіряти лише повідомлення означало б не
довести, що метрований рендер не стріляє.
