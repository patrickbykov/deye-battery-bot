# Теплокарта відключень

Стан на 7 вер 2026. Панель відповідає на два питання одразу: **скільки
загалом не було світла** і **коли саме вимикають**. Друге видно лише на
сітці доба × година — у стрічці по днях час доби губиться.

Команда бота `/outages` рендерить цю саму панель і додає підсумок текстом.

## Що є клітинкою

Одна клітинка — одна година доби одного дня, **за київським часом**.
Колір — скільки хвилин у цій годині не було мережі. Порожня клітинка
означає «даних немає», а не «світло було»: це різні відповіді, і плутати
їх не можна.

## Запит

```flux
import "date"
import "timezone"
option location = timezone.location(name: "Europe/Kyiv")

base = from(bucket: "monitoring")
  |> range(start: v.timeRangeStart, stop: v.timeRangeStop)
  |> filter(fn: (r) => r._measurement == "grid" and r._field == "voltage")
  |> filter(fn: (r) => r.inverter == "${inverter}")

points = base
  |> aggregateWindow(every: 1h, fn: count, timeSrc: "_start", createEmpty: true)
  |> keep(columns: ["_time", "_value"])
  |> rename(columns: {_value: "points"})

minutes = base
  |> aggregateWindow(every: 1m, fn: last, timeSrc: "_start", createEmpty: true)
  |> fill(column: "_value", usePrevious: true)
  |> map(fn: (r) => ({ r with _value: if exists r._value and r._value < 50.0 then 1.0 else 0.0 }))
  |> aggregateWindow(every: 1h, fn: sum, timeSrc: "_start", createEmpty: true)
  |> keep(columns: ["_time", "_value"])
  |> rename(columns: {_value: "minutes"})

join(tables: {m: minutes, p: points}, on: ["_time"])
  |> filter(fn: (r) => r.points > 0)
  |> map(fn: (r) => ({
       xMin: date.truncate(t: r._time, unit: 1d),
       yMin: float(v: date.hour(t: r._time)),
       count: r.minutes,
     }))
  |> group()
  |> keep(columns: ["xMin", "yMin", "count"])
  |> sort(columns: ["xMin", "yMin"])
```

Чотири рядки тут неочевидні, і кожен був знайдений на живих даних.

**`fill(usePrevious: true)` після похвилинного вікна.** Точки приходять раз
на пʼять хвилин, тож без ступінчастої функції відключення рахувалося б
кількістю точок, а не тривалістю. Похвилинна сітка дає інтегрування з
точністю до хвилини — більшої й не треба.

**`timeSrc: "_start"`.** `aggregateWindow` за замовчуванням підписує вікно
його **кінцем**. Хвилини з проміжку 14:00–15:00 лягли б у клітинку «15:00»,
і вся сітка виявилась би зсунутою на годину. Помітити це можна було б лише
звіркою зі справжнім відключенням, тобто через місяці. Заразом зникає
дубль-клітинка: останнє неповне вікно інакше дає другу пару (день, година)
з тим самим ключем.

**`filter(fn: (r) => r.points > 0)`.** Година, у якій не було жодної сирої
точки, дала б `0` хвилин без світла — тобто заяву «світло було», зроблену на
порожньому місці. Такі години викидаються, і клітинка просто не малюється.
Розрив, довший за годину, вже має власний алерт (правило 3, «обʼєкт
замовк»), тож це не замовчування.

**`option location`.** Без нього вісь годин була б у UTC, тобто зсунутою на
три години влітку й на дві взимку — рівно та вісь, заради якої панель
робиться.

## Поріг 50 В

Той самий, що в `helpers.js:GRID_PRESENT_VOLTS` і в правилі 4
(`grafana-alerting.md`). Якщо вони розійдуться, бот казатиме «мережа є» і
водночас рахуватиме цю саму хвилину як відключення. Максимум трьох фаз —
втрата однієї фази не є блекаутом.

## Як перевірити, не чекаючи темряви

Поки відключень не було жодного, сітка порожня, і відрізнити «рахує
правильно» від «завжди повертає нуль» неможливо. Спосіб — тимчасово
підняти поріг:

| Поріг | `outage` за 5040 хв спостережень |
|---|---|
| 50 В | 0 хв |
| 240 В | 2992 хв |
| 245 В | 4634 хв |

Числа монотонно ростуть із порогом — отже рахується справжня тривалість.
Виміряно 7 вер 2026.

## Межі, про які варто знати

- **Глибина = retention бакета, 30 днів.** Глибше даних немає; heatmap за
  рік вимагав би власної таблиці добових підсумків у SQLite.
- **Година спостережень зараховується як повні 60 хвилин**, навіть якщо
  точки в ній були лише пʼять. При кадансі 5 хв похибка мізерна, але вона є.
- **Розрив, довший за годину, стає порожнечею.** Якщо під час блекауту гине
  й звʼязок, найдовші відключення будуть невидимі — саме тому підсумок
  показує вікно спостережень поруч із цифрою, а не саму цифру.
